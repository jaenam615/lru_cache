# LRU Cache

이중 연결 리스트와 해시맵을 사용하여 구현한 LRU Cache입니다.  

## 구현 배경  
초급 개발자 면접에서는 다음과 같은 질문이 자주 나옵니다:  

> “배열(Array)과 연결 리스트(Linked List)의 차이를 설명해보세요.”

열에 아홉은 다음과 같은 내용으로 대답을 합니다:

- 배열  
  - "인덱스만 알고 있다면 임의접근을 할 수 있음으로 탐색이 O(1)로 매우 빠릅니다."
  - "반면, 삽입 및 삭제 시에는 후위에 오는 요소들을 재배치 시켜주어야 하기 떄문에, 최악의 시간 복잡도 O(n)을 갖습니다."
  - "메모리 공간에서 연속적으로 할당됩니다."
- 연결 리스트  
  - "노드의 요소 '값'과 '포인터' 중 포인터만 다른 노드로 라우팅하면 되기 떄문에 삽입 및 삭제가 최악의 시간 복잡도 O(1)입니다."
  - "메모리 공간 속 비연속적으로 할당되기에, 첫 노드부터 시작해야 합니다. 이 때문에 탐색은 최악의 시간 복잡도 O(n)을 갖습니다."

하지만 이후 의문을 느끼게 되었습니다.

> “그래서 실제 서비스나 시스템에서는 언제 연결 리스트를 사용하는가?”  
> "실제 데이터는 삽입과 삭제보다 조회가 훨씬 빈번하지 않나? 게시판만 봐도 글 작성빈도보다 조회빈도가 훨씬 높은데..."

조금 더 생각해보니, 연결 리스트의 포인터를 '엣지'로 생각하면 바로 트리였습니다. 이와 같이 "연결 리스트 그 자체보다는 다른 형태로 많이 쓰이곘구나?" 라는 생각이 들어 찾아봤습니다.  

찾아본 결과 가상메모리 페이징 알고리즘으로 학습해본 "LRU" 캐시가 이중 연결 리스트와 해시맵을 함께 씀으로 구현된다고 하여, 이를 직접 구현해보기로 했습니다.

## 문제 정의: 캐시에 필요한 요구사항

LRU 캐시는 다음 두 가지 요구사항을 동시에 만족해야 합니다.

1. **데이터 조회가 매우 빨라야 합니다**  
   - key를 통해 캐시 데이터를 즉시 조회할 수 있어야 합니다. (O(1))

2. **최근 사용 순서를 즉시 갱신하고 관리할 수 있어야 합니다**  
   - 어떤 데이터가 가장 오래 사용되지 않았는지를 바로 판단할 수 있어야 합니다.
   - 임의의 데이터를 중간에서 제거하거나 맨 앞으로 이동할 수 있어야 합니다.

이 두 조건을 배열 하나로 동시에 만족시키기는 어렵습니다.

---

### 왜 HashMap인가? 

```text
key → node
```

	•	key 기반으로 캐시 데이터를 즉시 조회하기 위함입니다.
	•	get, put 연산 모두 평균 O(1)의 시간 복잡도를 보장합니다.

다만 HashMap만으로는 데이터의 사용 순서를 관리할 수 없다는 한계가 있습니다.

## 왜 이중 연결 리스트인가?

이중 연결 리스트는 다음과 같은 상황에서 강점을 가집니다.  
	•	이미 노드의 위치를 알고 있는 경우
	•	노드 삭제: O(1)
	•	노드 이동: O(1)

LRU 캐시에서는 다음과 같이 사용됩니다.  
	•	가장 최근에 사용된 데이터 → Head
	•	가장 오래 사용되지 않은 데이터 → Tail

따라서,  
	•	get(key) 호출 시
→ 해당 노드를 리스트 중간에서 제거 후 Head로 이동
	•	캐시 용량 초과 시
→ Tail 노드를 제거

이 모든 작업을 O(1)에 처리할 수 있습니다.  

반면 단일 연결 리스트(Singly Linked List)는 다음과 같은 제약이 있습니다.  
	•	이전 노드를 참조할 수 없어
	•	중간 노드 삭제 시 O(n)의 탐색 비용이 발생합니다.

LRU 캐시는 임의 위치의 노드를 자주 제거하고 이동시키므로,  
prev와 next를 모두 보유한 이중 연결 리스트가 적합합니다.  

## 실무 관점에서의 의미

이 구현을 통해 다음과 같은 점을 이해하게 되었습니다.  
	•	연결 리스트는 단순히 “탐색이 느린 자료구조”가 아닙니다.
	•	순서가 자주 변경되는 데이터를 다룰 때 매우 효과적입니다.
	•	LRU 캐시는 실제로 다음과 같은 영역에서 사용됩니다.
	•	운영체제의 페이지 캐시
	•	데이터베이스 Buffer Pool
	•	웹 서버의 인메모리 캐시
	•	Redis 내부 캐시 구조

즉, 이중 연결 리스트는
현실 세계의 시스템 성능과 직접적으로 연결된 자료구조입니다.
